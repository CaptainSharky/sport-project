# Правила внесения изменений

## 1. Работа с ветками и Pull Request

Все изменения в основную ветку `main` вносятся только через Pull Request (PR). Прямые изменения `main` запрещены.

Для каждой задачи создается отдельная ветка (`feature/`, `fix/`, `docs/`).

Каждый PR должен содержать:
- краткое описание изменений;
- ссылку на задачу Jira;
- результаты тестирования, форматирования и статического анализа.

## 2. Правила Code Review

Каждый Pull Request должен получить одобрение минимум одного другого участника команды.

Рецензент выбирается с учетом области изменений: фронтенд, бэкенд или документация. Автор не может одобрять собственный PR.

При проверке оцениваются:
- соответствие требованиям задачи;
- качество и читаемость кода;
- корректность обработки ошибок;
- безопасность;
- соблюдение соглашений проекта;
- наличие необходимых тестов.

## 3. Исправление замечаний

Рецензент оставляет замечания в комментариях к PR.

Автор исправляет обязательные замечания в той же ветке и отправляет изменения на повторную проверку. Рекомендательные замечания обсуждаются с рецензентом.

Все обязательные замечания должны быть устранены до объединения изменений.

## 4. Условия объединения PR

Объединение изменений с `main` допускается только при выполнении следующих условий:

1. PR оформлен по установленным требованиям.
2. Получено минимум одно одобрение (`Approve`).
3. Обязательные замечания исправлены.
4. Необходимые автоматические проверки пройдены.
5. Отсутствуют неразрешенные конфликты с `main`.

История обсуждения, исправлений и одобрения сохраняется в GitHub.

Подробный регламент рецензирования изменений размещен в Confluence проекта.
